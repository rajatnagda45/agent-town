# Demo: supplier delivery discrepancy (Track 03 reasoning architecture)

**Story.** Purchase order PO-1042 ordered 100 units; receiving recorded 85. Was the shipment
short, was the receipt recorded wrongly, or are units still in transit? Agent Town investigates
with live Zetaris data, recalls earlier verified findings through H-MEM, applies an explicit
policy and recommends the next action. It never approves payment or changes records.

All records are **SYNTHETIC DATA** test records (`AGENT_TOWN_SUPPLIER_DEMO` in Zetaris), not a
real supplier incident. The figures come from the rows the system reads, never from code.

## Synthetic dataset

- **Source:** generated by `lib/server/supplier-demo-data.mjs`; every row carries
  `synthetic_label = "SYNTHETIC DATA"` and uses the project's license.
- **Size:** 3 purchase orders, 3 goods receipts, 4 shipments, and 3 supplier confirmations
  (13 rows total).
- **Scenarios:** day 1 records PO-1042 as 100 ordered, 85 received, and 15 in transit. Day 2
  records those 15 units as delivered without a second goods receipt. PO-1043 is complete,
  PO-1044 is short-shipped by 10 supplier-confirmed units, and PO-9999 does not exist.
- **Zetaris scope:** isolated Lightning database `AGENT_TOWN_SUPPLIER_DEMO` with
  `PURCHASE_ORDERS`, `GOODS_RECEIPTS`, `SHIPMENTS`, and `SUPPLIER_CONFIRMATIONS` tables.
- **Freshness:** status records expire after 24 hours. Generated files are written to the OS
  temporary directory and are not committed.

Regenerate, load, register, and verify the dataset with:

```sh
pnpm supplier:demo generate day1 # or day2; generates fresh timestamps
pnpm supplier:demo load
node --env-file=.env.local scripts/supplier-demo.mjs register # first run only
node --env-file=.env.local scripts/supplier-demo.mjs verify # read-only
```

## Before recording

1. Zetaris running (Docker `zetaris-*`), Nightshift on `:8088`, Agent Town started (`pnpm dev`).
2. Load day 1 (fresh timestamps; status records are valid for 24 hours):
   ```sh
   pnpm supplier:demo generate day1 && pnpm supplier:demo load
   node --env-file=.env.local scripts/supplier-demo.mjs verify
   ```
   First time only: `node --env-file=.env.local scripts/supplier-demo.mjs register`.
3. `pnpm hmem:conformance` → `13/13 checks passed` (evidence: `docs/evidence/hmem-conformance.txt`).

## The five stages (≈3 minutes)

| Time      | Stage       | Do                                                                                                                                                                                                                                                                                          | Show                                                                                                                                                                                                                                                                                     |
| --------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0:00–0:25 | 1 Request   | Group chat: _"Investigate the missing 15 units from purchase order PO-1042. Check the purchase order, goods receipts, shipment transfers and supplier records. Recall any previous findings and recommend the next action. Don't approve payment or change records without authorization."_ | "Supplier delivery investigation (PO-1042) started" with the Work link; planner, analyst and critic assigned                                                                                                                                                                             |
| 0:25–0:55 | 2 Evidence  | Open the Work report                                                                                                                                                                                                                                                                        | Execution timeline: `query submitted` / `query result` against `LIVE Zetaris · AGENT_TOWN_SUPPLIER_DEMO…`; **Findings and evidence** lists each row (PO, receipt, shipments, confirmation) with record ID, fields, timestamps and evidence ID                                            |
| 0:55–1:35 | 3 Challenge | Point at **Decisions and revisions**                                                                                                                                                                                                                                                        | The analyst's hypothesis, the critic's verdict and reason; a revision appears **only if the critic really sent it back** (never staged)                                                                                                                                                  |
| 1:35–2:25 | 4 Memory    | Load day 2 (`pnpm supplier:demo generate day2 && pnpm supplier:demo load`), then ask the same question again in chat                                                                                                                                                                        | **Memory** card: H-MEM recalls Run 1's verified finding (task ID, date, original evidence); fresh records now show the 15 units _delivered but not received_, so the badge reads **Conflicts with current records — not reused** and H-MEM confidence drops (timeline `memory feedback`) |
| 2:25–3:10 | 5 Decision  | Point at **Decision**                                                                                                                                                                                                                                                                       | Recommended action, confidence, the **Why** rules table (fired ✓ / —, reason, evidence IDs) and **Human approval required**: recording the receipt and approving payment; "no payment was approved and no record was changed"                                                            |

**Run 3 (honest failure).** Ask about `PO-9999`: no memory recalled, no substitute order, and the
report is **blocked** — "PO-9999 has no purchase order, receipt, shipment or supplier records".

## Narration lines

- "Instead of checking disconnected records manually, the agents collect the evidence into one investigation."
- "The first explanation is a hypothesis, not a fact. It must survive evidence and policy checks."
- "Agent Town remembers what it learned about this order, but never treats yesterday's evidence as proof of today."
- "The result is an auditable recommendation, not an unauthorized transaction."

## What is real, and what is not

| Claim                    | Status                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------- |
| Zetaris queries and rows | Live reads of `AGENT_TOWN_SUPPLIER_DEMO` (synthetic, labelled)                        |
| H-MEM                    | Meterless reference engine, vendored unmodified; official suite 13/13                 |
| Policy decision          | Deterministic rules in `lib/server/supplier-policy.mjs`; the model never decides      |
| Confidence               | Heuristic: share of the gap supported by current records, halved if evidence is stale |
| Revision                 | One critic-driven round is supported; shown only when it occurs                       |
| Real supplier systems    | Not connected                                                                         |
